# AGENTS.md

## Project overview
- **Paperite** is a local-first desktop note-taking app built with React, Electron, and Vite.
- Notes are stored as JSON files in `~/Documents/Paperite` with a local SQLite index (via `node:sqlite`).
- Authentication uses Clerk (test key in `.env`).

## Commands
- **Dev**: `bun start` (runs `bun run dev` which launches Vite + Electron concurrently)
- **Build**: `bun run build` (runs `tsc -b && vite build && electron-builder`)
- **Browser build**: `bun run build:web` (required before browser QA so `dist-web/` is current)
- **Browser server**: `bun run serve` (serves the built web app for browser QA)
- **Lint**: `bun run lint` (runs `biome check .`)
- **Format**: `bun run format` (runs `biome format --write .`)
- **Typecheck**: `tsc -b` (part of build, no separate script)

## Browser QA on Linux
- **Paperite is an Electron app.** For browser QA, always build the browser
  artifact first with `bun run build:web`, then serve that artifact with
  `bun run serve`. Never use the Vite dev renderer or an arbitrary/stale
  server process for full-app browser QA.
- When testing Paperite in a browser, always run `bun run build:web` first, then use `bun run serve`.
- Do not use the Vite-only renderer (`bun run dev:web`) for full app QA; it has no Electron bridge and cannot access the local workspace/editor path.
- Use Codex/T3 browser preview against the `bun run serve` URL. Browser QA does not require macOS or Electron computer-use.

## Architecture
- **Electron main process**: `main.js` (CommonJS, uses `node:sqlite` for indexing)
- **Preload bridge**: `preload.js` (exposes `window.electron` API via IPC)
- **Renderer entry**: `src/main.tsx` → TanStack Router (file-based routing)
- **Routing**: `src/routes/` with auto-generated `src/routeTree.gen.ts` (do not edit manually)
- **UI**: shadcn/ui components in `src/components/ui/` (radix-nova style, Tailwind CSS v4)
- **Path alias**: `@/` maps to `./src/` (configured in tsconfig and vite)

## Key conventions
- Package manager: **bun** (v1, `packageManager: "bun@1"` in package.json)
- Linter/formatter: **Biome** (recommended rules, formatter enabled)
- UI convention: never use the Tailwind class combination `uppercase tracking-wider`.
- TypeScript strict: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`
- Note content format: TipTap JSON structure (see `src/lib/note-content.ts`)
- Notes engine API: `src/lib/notes-engine.ts` (wraps Electron IPC calls)
- T3 subagents: prefer the `codex_quatenary` provider for delegated work; use
  OpenCode's `opencode/beam-free` model only as the fallback.

## Gotchas
- `src/routeTree.gen.ts` is auto-generated by TanStack Router plugin — never edit by hand.
- Electron main process uses `node:sqlite` (requires Node 22+ runtime).
- Dev server must be ready before Electron launches (handled by `wait-on` in dev script).
- Clerk publishable key in `.env` is a test key — replace for production.
- No test suite exists; no CI workflows configured.
